# OnePledge · Wave 2 demo video

Target length: about 1:30. Twelve short lines, roughly 230 spoken words at a calm pace.
Record each line as its own take; the edit adds the pauses. Same voice and pace as Wave 1.

This is a *what changed* video, not a re-explanation. Lines 1–2 are the only recap.

| # | On screen | Narration |
|---|---|---|
| 1 | Landing page, seal pressing the wax | OnePledge is a registry on Midnight that refuses to let the same invoice be financed twice, without any lender seeing another's book. |
| 2 | Wave 1 security review, F10 highlighted | In Wave One we shipped it — and published what was still wrong with it. |
| 3 | F10 text: "no void path" | A borrower could pledge an invoice to any admitted lender without asking. The receivable was used up forever, whether or not that lender ever financed it, and nothing could undo it. |
| 4 | Walkthrough: step 3, two buttons | In Wave Two the lender decides. |
| 5 | Walkthrough: decline, tags go to none | If the lender refuses, the receivable is released, and the public set stops claiming it is encumbered. |
| 6 | Walkthrough: pledge the freed invoice to Lender B | The borrower takes it elsewhere, and the registry accepts it — the same invoice it refused a moment earlier. |
| 7 | Lender B card: "never sees that Lender A refused" | Lender B finances it, and never learns who turned it down, or on what terms. |
| 8 | Two-lender slide | This is why the registry works with two lenders. No consortium has to form first, because the only thing either one learns is a single fact about a single invoice: already pledged. |
| 9 | Desk page, 1AM connected, preflight green | The desk connects a real Midnight wallet, builds the full provider stack, and checks what a pledge still needs before it lets you sign. |
| 10 | Preprod explorer, v3 transactions | All of it runs on Midnight Preprod. Registry version three, deployed and exercised: a pledge accepted, a double pledge refused, a pledge declined, and the freed invoice financed by someone else. |
| 11 | Test output, KSeF spec diff | Two hundred tests, and a privacy allowlist on every value a circuit publishes. Reading the Ministry's own specification this wave, we found that one invoice has two legal spellings — which is exactly the gap this project exists to close. Both now resolve to one tag. |
| 12 | Closing card: hosted URL, repository, contract address | OnePledge. One pledge per invoice, and now the lender gets a say. |
